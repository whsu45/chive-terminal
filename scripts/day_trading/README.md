# day_trading — 當沖多空勝率監控（本機執行，不走 GitHub Actions）

把「盤前籌碼 + 盤中強弱 → 多空勝率 → 支撐壓力與進出場價位」這套判斷流程固定成腳本，
每 3 分鐘重算一次，直到你按 Ctrl+C。全部只用 Python 標準庫，永豐 Shioaji 為選用強化。

```bash
cd scripts/day_trading
python3 monitor.py 3042 --web               # 本機網頁儀表板 http://127.0.0.1:8770/（盯盤用這個，會自動開瀏覽器）
python3 monitor.py 3042                     # 純終端輸出，族群自動查 groups.json
python3 monitor.py 3042 --peers 2484,8081   # 自訂同族群
python3 monitor.py 3042 7704 --interval 180 # 多檔、估算改三分鐘一次（預設 60 秒）
python3 monitor.py 3042 --once --verbose    # 跑一次並印每個因子的理由
python3 monitor.py 3042 --once --json       # 單次、JSON 輸出（給程式或 AI 讀）
python3 prep.py 3042 --refresh              # 只重抓盤前資料
python3 theme_screener.py                   # 盤前選股：FinLab 概念股主題 → 前 3 多、前 3 空與理由（--top 5 / --json）
python3 review.py                           # 收盤後復盤今天 monitor 的訊號與結果
python3 replay.py 1815 --step 5             # 盤後重播：用永豐逐筆重建「若從 09:00 監控」每 5 分鐘的判斷
python3 calibrate.py --apply                # 重新校準大單/散戶金額門檻（monitor 會在過舊時自動跑）
python3 calibrate_warrants.py               # 驗證權證多空與標的漲跌的關係
```

monitor.py 啟動時會檢查上次 `calibrate.py` 的日期：超過 `CALIBRATE_MAX_AGE_DAYS`（預設 45 天）就重跑並回寫 `.env`；
盤前／盤後立刻跑，盤中（08:45–13:35）不抓歷史逐筆，改在收盤後補跑。校準的基期會隨盤勢改變（例如 9–10 月是下跌盤），
所以這個檢查不要關。

`--web` 會在本機（只綁 127.0.0.1，不對外）開一個儀表板：
**兩種節奏**：多空勝率、因子、進出場計畫每 `--interval` 秒（預設 **60**；估算很輕，MIS 只多一次呼叫）重算一次；
江波圖、報價、五檔、主力/散戶分流、權證快照與即時警示由另一條快迴圈更新（`/api/live`）：
MIS 每 10 秒抓一次（限流），**有 Shioaji 時每 3 秒用逐筆串流覆寫成交價、高低、量與五檔**（BidAsk 訂閱），
頁面每 3 秒拉一次；即時卡右上會標「逐筆」或「MIS hh:mm:ss」告訴你這筆價格來自哪裡。
主力分流劇變（急回補 / 急出 / 加速出貨 / 拉高出貨）與權證異動的 ⚠ 由快迴圈即時發出，不用等下一次估算；
**所有警示都帶時間戳，60 秒內的新警示會閃爍**。

**建議做空 / 做多橫幅**（頁面最上方，會一直脈動發光）：看盤時不用盯所有數字，快迴圈每 3 秒檢查「進場確認條件是否已經發生」，
成立才掛出 `▶ 建議做空 217.5`（含停損、目標、勝率、起始時間、現價），同時進警示與瀏覽器分頁標題。條件：
模型那一邊勝率 ≥60%，且 (a) 主計畫：最近 12 根 1 分 K 碰過壓力/支撐、最後一根完成的 1 分 K 收在進場價之下/之上、現價仍在進場價附近；
或 (b) 備援：最後一根完成的 5 分 K 帶量（≥1.5 倍前 6 根均量）收破支撐 / 收過壓力、現價離觸發價 1% 內。
反彈動能中不給空、殺盤動能中不給多、權證急漲+委買厚時不給空；09:10 前與 13:20 後不給。
訊號掛到：到目標 1（✔）、過停損（✘）或成交後 30 分鐘（記平，跟結案判定一致），結束後虛線再顯示 2 分鐘；同一個點 15 分鐘內不重發。
**進場後只看停損/目標，不因中途回吐提早跑**：盤中警示（主力急出、權證急漲＋委買厚、買單牆快被吃完）只說「不要新進」，不叫已進場的減碼或收緊停損；防護放在進場前（追價上限、逆勢過濾、撤單警告）。

**大戶散戶卡**（籌碼K線「大戶散戶」同款，在分流卡下方）：頂端「大戶控盤 / 散戶控盤」標籤與大戶、散戶成交量比例條，
下面兩張圖是大戶（主力）與散戶的**累積買賣超**每分鐘柱狀面積（紅＝買超、綠＝賣超、x 軸 09:00–13:30），
標題印累積張數與本分鐘買進/賣出張數。資料來自 `src_shioaji.flow_history`（全日逐筆每 10 秒重算一次），需要永豐串流。

**掛單牆追蹤**（五檔卡下方）：五檔中某一檔 ≥2 倍其他四檔平均且 ≥max(30 張, 0.5% 今量) 就開始追，每 3 秒記被吃（該價成交）、
撤單（掛單減少卻沒成交）、補單。被吃 ≥30% 仍在且撤單少 →「真支撐/壓力傾向」⚠；價格靠近就撤、幾乎沒成交 →「假」；價格穿過 →「被吃穿」。
真支撐擋在空單目標前時不發做空訊號（真壓力同理）。11/05 晶豪科 13:00 215 掛 103 張，13:01 被打到成交 84 張仍掛 80、價彈回 216.5，是真支撐。

**尾盤規則**：13:05 起不發新進場訊號（當沖平倉主導，只處理出場或順回補方向小部位）；12:50 後若跌 ≥4%、散戶淨賣、主力 10 分鐘淨額回升 →
「尾盤空單回補」+0.3（反彈是回補不是看多，勿追空也勿追多）；漲 ≥4%、散戶淨買、主力在出 →「尾盤多單出場」−0.3。

**交戰紀錄**（`logs/stock_history.json`，儀表板「交戰紀錄」卡、分頁上的「N天」）：當沖做熟悉的股票。每檔記監控過哪些天
（同一天開幾次都算一天）、啟動次數、每一次建議訊號的結果與可疑原因、備註（`history.add_note(code, text)`）。
`model.evaluate` 會參考：某一邊的訊號勝率 ≤35%（至少 4 筆有結果）就把那一邊勝率扣 8 並警告「這邊的劇本在它身上不靈」；≥65%（≥6 筆）加 4。
`/api/watchlist` 列全部個股的監控天數與勝敗（卡片底部「常做個股」）。

**追價上限 / 進場區**：訊號條件成立時，進場區 = 觸發價 ～ 進場價 + 1/3 停損距離，且區內任一價位報酬風險比 ≥1.5（目標太近、整區湊不到就不發）。
現價在區內 → 「▶ 建議做多 @現價」；已追出區外 → 「▶ 建議做多 掛 X–Y」（虛線框不閃），價格回到區內才「▶ 掛單成交」，
先到目標 1、20 分鐘沒回、或過 13:05 → 「○ 未成交」，不算輸贏。11/06 的 6 個訊號掛出時已走了停損到目標的 25–75%，兩筆輸的報酬風險比都 <1，因此加上。

**逆勢過濾**：訊號條件都成立，但大盤或族群最近 10 分鐘往反方向走就不發——強烈反向（大盤 ≥0.6% 或族群平均 ≥1.0%）直接擋；
溫和反向（大盤 ≥0.3% 或族群 ≥0.5%）在另一個沒有同向支持時擋。儀表板訊號區顯示「⏸ 逆勢過濾」與理由，警示也記一則；
被擋的訊號照樣追蹤「假設進場」的結果（`signal_outcomes.jsonl` 標 `blocked`，不進交戰紀錄勝率），結案發「⏸ 過濾驗證：…擋對了/擋錯了」，
`signal_review.py` 最後列「逆勢過濾驗證」。backtest_entry.py 顯示事後看大行情逆勢勝率只有 17%，所以先擋逆勢、再談進場價。
族群趨勢要 `groups.json` 有定義；11/06 新增 AI伺服器ODM、導線架、不鏽鋼。

**漲跌停過濾**：價格在漲停（委賣沒單 = 鎖死買不到；有委賣也沒上漲空間）不發做多，跌停對稱不發做空；目標 1 超過漲停 / 低於跌停也不發。
警示記「⏸ 漲跌停過濾」，同一檔 15 分鐘一則；根本成交不了，所以不追蹤假設結果。

**急漲過濾（不放空急漲股）**：比昨收漲 ≥7%、或離漲停 ≤3% 不發做空（跌 ≥7% / 離跌停 ≤3% 不發做多）。
不是期望值差：全市場 2026/03–11 共 1484 筆開盤跳空 7–9.5%（沒鎖漲停），開盤空、收盤補平均反而 +1.5%；
擋它是因為回測算不到的尾端風險——這類股票 67% 盤中碰漲停、45% 收漲停，鎖住時停損買不回來、當沖可能要標借。
擋下的照樣追蹤假設結果（「⏸ 急漲過濾」），`signal_review.py` 分開列「急漲過濾驗證」。

**弱勢股篩選**（`weak_screen.py` 每晚清單 + 盤前因子「弱勢股篩選」）：前一交易日收盤 劣於大盤（10 日報酬 < 加權 10 日報酬）、
10 日跌 >10%、收盤 < 季線、股價 >100、外資和投信都賣超，五條件全中。回測 2026/05/28–11/05（109 天，隔天開盤空、收盤補，未扣成本）：
大盤弱（加權 < 20 日線，41 天、461 筆）+1.10% vs 所有 >100 元股票 +0.77%，多 0.33%，前後半段都成立、勝率 60%；
大盤不弱（68 天）−0.15% vs +0.22%，反而比隨便空差。所以只有大盤弱時給 −0.4 偏空因子，大盤不弱只提醒「弱勢股常反彈，別因為弱就空」。
注意基準本身就是正的（這段期間開盤空、收盤補所有股票平均 +0.42%），判斷條件有沒有用要看贏過基準多少。
`python3 weak_screen.py`（`--date`、`--near` 另列差一條件的）；全市場資料快取在 `.cache/screen_daily.json`，第一次抓約 65 天、之後每天補一天。

**測過、沒採用的 Threads 手法**（2026/11）：
- 盤中「反彈挑戰前高 + 無量上影 + KD 高檔轉折 + 大單順勢砸 → 空」：9 檔 × 42 天逐筆，全套 219 筆扣成本每筆 −0.25%，同時段隨便空 −0.21%；
  換三種出場都沒贏。只在事後才知道的大跌日（開→收 ≤ −3%）有效，但那種日子隨便空也有效——貼文例子都是事後挑的大跌日。
- 避開「在 VWAP 上下來回穿越」的股票：模型同構訊號 4322 筆依訊號前 15/30/60 分鐘穿越次數分組，每筆結果沒有穩定差異，不做硬性過濾。

**撤單警告（掛單被大單砸穿）**：等回的掛單還沒成交、價格到了掛單價 1 tick 內，而且最近 15 秒是被**大單**從 ≥3 tick 外砸過來的
（做多看內盤大單賣、做空看外盤大單買，大單門檻跟分流同一套）→ 發「⚠ 撤單 做多 掛 X」，訊號結束、不算進場。
要逐筆內外盤，只在永豐串流模式運作。撤掉的照樣追蹤「沒撤會怎樣」（`signal_outcomes.jsonl` 標 `cancelled`，不進交戰紀錄勝率），
結案發「⚠ 撤單驗證：…撤對了/撤錯了」，`signal_review.py` 最後列「撤單驗證」。
回測（`backtest_entry.py --burst-cancel`，9 檔 × 42 天）：會被撤的 117 筆若照成交每筆淨 −0.37%，全部平均 −0.22%，前後半段都比較差；
放寬到「30 秒 ≥2 tick」撤 506 筆，但那些只比平均差 0.02%，等於只是少做，所以只撤砸得很兇的。

**持倉面板（儀表板訊號下方，全部用點的）**：訊號一出來就有三個排隊價可點——建議價、再划算 1 tick、2 tick（做多往下、做空往上），或「不做」。
點了之後模型改盯**你的**單：
- 排隊中：顯示現價差幾 tick；撤單警告改看你的排隊價（15 秒內被大單從 ≥3 tick 外砸過來 → 面板變紅、撤單鈕變主按鈕）；價格到了提示按「✓ 成交」。
- 持倉中：即時顯示賺賠幾 tick、扣成本 %、距停損/目標幾 tick 和一條停損↔目標的位置條；到停損「⛔ 照紀律出場」、到目標「✔ 照計畫出場」、13:20 提醒平倉。
  出場三顆鈕：現價／停損價／目標價。不因中途回吐叫你跑。
- 點錯 60 秒內可「↶ 復原」。重啟 monitor 會重放今天的事件恢復狀態。
- **沒點任何東西**：模型不假設你有單，訊號結案的提醒都標「（模型假設）」。
- 事件記在 `logs/trades.jsonl`，`signal_review.py` 最後列「你的實際交易」（扣成本損益、成交價比建議價好多少）。
  **這是個人交易紀錄，repo 是公開的，所以不推**：已在 `.gitignore`、`sync_logs.py` 也排除；持倉相關的提醒只顯示在儀表板，不寫進 monitor/alert log。
- POST `/api/position` 只綁 127.0.0.1、要 JSON 且 Origin 是本機。

**急殺急拉、V 轉的其他防護與回測結論**（9 檔 × 42 天逐筆，1664 次 10 分鐘內急動 ≥ max(0.8%, 2.5 倍平常 10 分鐘波動)）：
- 急動當下順勢追進，5／10／20 分鐘後平均都是虧的（−0.09%，5 分鐘後只有 31% 是賺的）；之後先回吐一半（V 轉）50%、先再延伸一半 36%。
  模型的訊號本來就要拉回到價位、1 分 K 確認才發，不是追急動，回測裡急動後發的訊號沒有比較差，所以不另外加過濾。
- 已經在 `_momentum`（連 4 根同向 1 分 K、≥1.2%，從日低/日高出發）擋反向訊號，`大盤急拉/急殺` 與逆勢過濾處理指數 V 轉。
- 持倉中「浮盈回吐一半＋反向主動量 → 先出」測了 8 組參數全部比原本差（砍掉的贏單跟救回的輸單差不多），不做。

**訊號輸贏判定**（`logs/signal_outcomes.jsonl`、`signal_review.py`）：每則「建議做空/做多」結案時判（等回掛單用掛單價、從成交那分鐘起算，沒成交記 nofill）：成交後 30 分鐘內先到目標 1 = 贏、先到停損 = 輸、
都沒到 = 平；**5 分鐘內反向走掉停損距離一半 = 估錯（fast_adverse）**，即使之後賺回來也記。輸或估錯的會列「可疑原因」（當時就看得到的條件：
大盤/族群/主力 10 分鐘反向、反向動能、五檔反向厚、權證急漲、散戶同向擁擠、尾盤、量縮、日內極端位置追單、真牆擋在前面），
並即時發一則 ✔/✘ 警示。`signal_review.py` 算各檔各方向勝率、估錯率，以及每個條件在輸單 vs 贏單的出現率（提升度 >1.5 就該加進過濾條件）。

**因子權重演化**（`evolve.py` → `model_params.json`）：用 `logs/monitor_*.jsonl` 每輪估算的因子與 30 分鐘後的漲跌當答案，
基因演算法調每個因子的權重倍數（0–2.5）、勝率斜率 scale、盤前權重 daily_w，適應度是 Brier 分數加偏離 1 的懲罰；
先 walk-forward（最後一天當測試）看有沒有變差，再 `--apply` 寫 `model_params.json`，`model.evaluate` 自動載入（因子說明會標「權重 ×k」）。
樣本 <300 拒絕套用；幾天的資料只反映那幾天的盤勢，倍數先當方向參考，和「因子方向命中率」表一起看。

**資料來源標記**（`src`）：每筆估算（`monitor_*.jsonl`）、警示結果、訊號結果、交戰紀錄都標 `shioaji`（永豐逐筆串流）或 `mis`（沒有永豐金鑰，只有證交所公開報價 10 秒快照）。
MIS 模式的 1 分 K 是快照拼的、會漏高低點，也算不出主力/散戶分流與即時五檔，所以同一檔同一時間兩台機器掛出的進場點可能不同。
交戰紀錄勝率與 `evolve.py` 預設**排除 `mis`**（`--include-mis` 才納入）；`signal_review.py` / `alert_review.py` 分來源列，可用 `--src mis|shioaji|unknown` 篩（unknown = 加欄位前的舊紀錄）。

**多台電腦（裝置 ID）**：每台第一次執行時隨機產生一個裝置 ID，存在 `.device_id`（已 `.gitignore`，不能進 git，否則兩台會拿到同一個 ID）。
monitor 啟動時會印出 `[裝置] ID xxxxxx`。每台寫自己的檔，所以兩台同一天都開 monitor、收盤各自推送也不會撞檔：
`logs/monitor_YYYYMMDD_<ID>.jsonl`、`logs/alert_outcomes_<ID>.jsonl`、`logs/signal_outcomes_<ID>.jsonl`、`logs/stock_history_<ID>.json`、
`.cache/daily_<代碼>_<日期>_<ID>.json`、`.cache/calibration_<日期>_<ID>.json`。不用電腦名稱，主機名不會出現在公開 repo。
想取好認的名字可設環境變數 `DEVICE_ID=mac`（小寫英數與 `-`，最多 16 字）。
讀取時（`review.py`、`alert_review.py`、`signal_review.py`、`evolve.py`、交戰紀錄）合併所有裝置，以及加 ID 前沒有後綴的舊檔；
同一天同一檔兩台都有紀錄時**只算一台**（永豐串流筆數多的優先），不重複計勝率。盤前資料會先用自己的快取，沒有就沿用別台推上來的同日快取。
`logs/trades.jsonl`（持倉面板）本來就只留本機，不受影響。

**警示結果追蹤**（校準用）：快迴圈對每則 ⚠/▶ 警示記下當時價格、日內位置、主力淨額與 10 分鐘變化、五檔不平衡，
10 / 30 分鐘後用分 K 補上報酬與期間最高最低，寫 `logs/alert_outcomes.jsonl`；`python3 alert_review.py`（`--type 認購權證急漲 --low --cover --detail`）
統計各類警示之後漲跌的比率，用來決定哪些警示該升格成訊號。11/05 晶豪科五次認購權證急漲：2 次後跌 3%、1 次漲 2.6%、2 次持平，
成功那次是低檔雙底 + 主力停賣 + 委買厚，所以單獨的權證急漲只當提醒。

**每日資料進 git**：收盤後（13:35）monitor 自動跑 `sync_logs.py`，把 `logs/*.jsonl|json`（估算紀錄、警示/訊號結果、交戰紀錄）、
`.cache/daily_*.json`（盤前資料）、`model_params.json` commit 並 push 到 GitHub；`.env`、`.cache/http/`、`.cache/ticks/` 永遠不進。
手動：`python3 sync_logs.py`（`--no-push` 只 commit）；`LOG_SYNC=0` 關掉自動同步。

**ticks 額度**：永豐盤中 `api.ticks` 每日 10 次，每次啟動每檔用 1 次（回補當日逐筆）。所有呼叫都經過 `src_shioaji.fetch_ticks`
記到 `.cache/ticks_usage_YYYYMMDD.json`，啟動時印「今日 ticks 已用 N/10」，儀表板右上也顯示；≥8 會變橘色，當天就別再重啟。

**盤中才啟動**（例如 09:30 才打開）：有 Shioaji 時逐筆用一次 `api.ticks` 回補到 09:00，分 K、VWAP、主力/散戶分流都是全日的；
另外用回補的逐筆重建「每分鐘主力/散戶淨額」（`src_shioaji.flow_history`），所以 `_flow_dynamics` 立刻有 10 分鐘以上的歷史，
而且 09:00 起該出的分流警示會補發（帶原本的時間戳）。加權/櫃買用一次 `kbars` 回補。
回補不到的：權證「一輪內急漲」這類需要前一輪快照的警示（啟動後下一輪才開始）、五檔歷史。沒有 Shioaji 時只有啟動後的區段。

版面：上排三張**江波圖並排**（加權、櫃買、個股；x 軸固定 09:00–13:30，虛線分隔 10:30 / 12:00 時段，
昨收為中線、紅漲綠跌、黃線 VWAP、下方成交量），**買賣點直接畫在個股圖上**：灰色虛線「壓/撐」是計畫要先測試的價位（觸發價），
主計畫那一邊的「空進/多進」實線是測試失敗後才掛的進場價（空＝綠、多＝紅），停損橘色虛線、T1/T2 點線，另一邊淡化。
計畫文字寫明確認條件：「碰 X 不過：1 分 K 收 Y 以下才進」；反彈/殺盤動能中會在計畫上方加「先不進，等 1 分 K 翻黑/翻紅」。右上角是**時段標籤**（早盤 09:00–10:30 / 中盤 10:30–12:00 / 尾盤 12:00–13:30，
滑鼠停留看該時段策略，多空勝率卡下方也會印），其餘卡片：即時價量、多空勝率條（含下次估算倒數）、警示、因子、進出場計畫、
壓力支撐階梯、分流、五檔、族群（含領漲股）、權證、勝率曲線、盤前摘要；多檔用上方分頁切換。

資料來源：有 Shioaji 時個股分 K 由逐筆成交聚合（啟動時回補當日）、加權/櫃買由指數串流 + 一次 kbars 回補；
沒有 Shioaji 時改用 MIS 每 10 秒取樣湊分 K（只有啟動後的區段）。MIS 在「瞬間價格穩定措施」延緩撮合的 2 分鐘內
沒有成交價、五檔是試算價，程式會把參考價夾回今日高低並發 ⚠ 提醒（11/03 建榮 09:24 試算 96.65、真實高點 93.5）。
台股慣例：紅漲綠跌。終端同時印一行摘要。收盤後伺服器不會結束，可繼續看當天資料。

啟動時先印一次盤前資料（法人、融資券、借券、分點、技術面、夜盤、美股），
之後每輪印：即時價量、大盤與族群相對強弱、五檔、（有 Shioaji 時）大單/散戶分流、
多空勝率、警示、支撐壓力、空單與多單的進場/停損/目標。
每輪結果都 append 到 `logs/monitor_YYYYMMDD.jsonl`，`review.py` 讀它做復盤。

全部只用標準庫，Windows 直接能跑；差別只在啟動指令與編碼：


  Windows Terminal / PowerShell 7 顯示正常；舊版 cmd 不會當掉，只是「≥ ⚠ ▶」這類符號顯示成 ?。盯盤請用 `--web`，網頁不受影響。

- **`[SSL: CERTIFICATE_VERIFY_FAILED]`／「連不上證交所 MIS」**：公司網路或防毒軟體在做 HTTPS 檢查，換上了自己的根憑證，

  1. `py -3 -m pip install -U certifi`（程式會自動加讀）
  2. 跟 IT 要公司根憑證（Base64 的 .pem/.crt），設 `set DAYTRADE_CA_BUNDLE=C:\path\corp-root.pem`（Git Bash：`export DAYTRADE_CA_BUNDLE=/c/path/corp-root.pem`）
  3. 換一個沒有 HTTPS 檢查的網路（例如手機熱點）確認是不是公司網路造成

## 永豐 Shioaji（選用）

1. `python3 -m pip install -r requirements.txt`
2. `cp .env.example .env`，把 **API Key / Secret Key 填進 `.env`**（這個檔已在 `.gitignore`，不會進 git；
   不要貼到任何 `.py`、`.json`、聊天或 commit 訊息裡）。
3. `SHIOAJI_SIMULATION=1` 用模擬環境（行情相同、不能下單），確認可用再改 0。

有金鑰時腳本會：登入 → 用一次 `api.ticks` 回補今日逐筆 → 訂閱逐筆成交串流，
把每筆成交分成主力/中實戶/散戶、依內外盤分買賣，算出主力淨買賣、散戶淨買賣、藏單、外內盤比、VWAP。

**大單門檻不是固定張數。** 1 張台積電約 230 萬，同樣的錢可以買 150 張友達，所以用金額：
- 大單 = 單筆金額 ≥ `BIG_LOT_AMOUNT`（預設 300 萬，校準值），且不低於該股**當日單筆成交張數的 95 分位**
  （流動性好的股票 500 萬可能只是常態單，分位數把門檻抬到該股真正的異常大單）。
- 散戶 = 單筆金額 < `SMALL_LOT_AMOUNT`（預設 100 萬），1 張單一律算散戶。中間是中實戶，不計入兩邊。
- `--big-amount 3000000` 臨時改金額；`--big-lot 30` 或 `.env` 的 `BIG_LOT_THRESHOLD` 才會固定張數。
- 啟動時先用昨收推算一次門檻印出來，開盤後每輪用當日分布修正。

**規律小單（藏單）偵測。** 主力常用演算法把大單切成固定張數、固定方向、近似等間隔的小單慢慢買或賣，
張數看起來像散戶。`detect_iceberg()` 找出「同張數＋同方向」出現 ≥8 筆、佔筆數 ≥12%、同方向占比 ≥75% 的組合，
再看間隔的變異係數（cv ≤0.9 判為機器單）。符合的量從散戶改歸主力（輸出中的「藏單」），
模型加「規律小單吃貨 +0.45 / 規律小單出貨 −0.45」因子。**不會**每 3 分鐘輪詢 `ticks/kbars`：
官方限制盤中 `ticks` 查 10 次/日、`kbars` 270 次/日，盤中輪詢歷史查詢會被停權。
沒金鑰或沒安裝套件時，這一塊自動停用，其餘功能照常（五檔與價量改用證交所 MIS）。

|---|---|---|
| 大單金額 | 100 萬～2,000 萬 | 早盤 20 分鐘主力淨買% 對 09:20→09:50 報酬的 IC 在 −0.02～−0.08，**所有門檻都沒有預測力**，命中率 46–49%。全日主力淨買對隔日報酬也是負的（−0.03～−0.08）：大單買進隔天偏跌，就是隔日沖庫存效應。選 300 萬只因它最不差。 |
| 散戶金額 | 20 萬～200 萬 | 散戶淨買% IC 穩定在 −0.10～−0.12（反指標），100 萬最好。散戶淨買 ≥15% 量時接下來 30 分鐘**只有 15% 機率上漲、平均 −0.62%**（n=20）；5～15% 時上漲 43%、平均 −0.27%。 |

所以模型裡「大單淨買」只給 ±0.15 當資訊，「散戶瘋搶」給 −0.6、「散戶追價」−0.3。對照組：09:20 相對開盤的價格動能 IC −0.04，也沒有預測力；
這兩個月是下跌盤（09:20→09:50 上漲基期約 42%），結論要定期重跑校準確認。各檔單筆成交張數 P95 多在 6–22 張，
500 萬在中低價股等於 P99 以上的罕見大單，這是改用金額加分位數的原因。

### 盤中權證異動 → 現股風險提醒（只提醒，不進分數）

monitor 每輪記住每檔權證的價量，跟上一輪比（成交量加權、只算這一輪有新成交的），出現以下情況就在警示區印 ⚠：

| 觸發 | 提醒內容 |
|---|---|
| 認購在一輪內急漲 ≥12%（≥50 張換手） | 散戶追價、發行商避險買盤同步進場；現股空單有軋空風險 / 現股未漲而權證先漲要留意急拉 |
| 認購在一輪內急跌 ≥12% | 權證多單停損，發行商回補避險部位會賣現股；現股多單守不住開盤價就走 / 跌勢可能加速 |
| 認售在一輪內急漲 ≥12%（≥30 張） | 空方透過權證進場，發行商放空現股避險，現股多單風險升高 |
| 認購今日中位漲幅 ≥30% / ≤−30% | 獲利盤隨時出、發行商反手賣現股 / 多方已被洗出、再殺空間變小 |
| 現股 \|漲跌\| <1% 但認購中位已動 ≥15% | 發行商調隱含波動率或市場搶先定價，現股波動將放大 |
| 一輪權證成交 ≥ 昨日全日認購量 8% | 瞬間爆量，現股即將或正在劇烈波動，部位先減半 |

所以「權證做多標的容易漲」只對**同一天**成立，而且因果是反的：標的漲 → 散戶追認購 → 發行商買現股避險 → 再推一段。
當沖可以把盤中認購爆量當順勢確認（不留倉），但不能把前一天的認購熱度當隔天的多方理由；避險部位重的隔天反而偏空。

勝率 = 50 + 11 × 偏多分數（盤前因子 ×0.8 + 盤中因子；試撮期間盤中因子 ×0.5），再依量縮/低波動扣分，
夾在 15–85%。兩邊差 <8 個百分點 → 觀望。進出場價以最近的壓力/支撐（今高低、昨收、開盤、MA、布林、整數關卡、VWAP）
為主，停損在關卡外 max(2 tick, 0.15 ATR)，目標為下一與再下一個關卡。

## 還沒自動化、但判斷時應該納入的資料

- **集保股權分散（大戶持股比）**：每週五公布，400 張以上持股比連續增減。TDCC 開放資料只有當週全市場 CSV，
  要抓歷史需逐檔查詢表單，先列為手動核對。
- **主力連續買賣天數 / 分點進出成本**：目前只算昨日與 4 日淨額；分點的平均成本（有沒有套牢）需要再抓 zco 的買賣均價。
- **當沖比率、現沖成交占比**：TWSE `TWTB4U` 每日當沖統計，可判定該股是不是當沖客主場（高當沖比 → 尾盤必有平倉賣壓）。
- **自營商避險 vs 自行買賣拆分**（T86 已有欄位，尚未分開計分）。
- **法說會/重訊/營收公告時程**：月底作帳、法說前後的題材行情，目前靠你人工標註（如光寶科 10/30）。
- **Shioaji scanners**（漲跌幅/成交量排行）與**全市場即時族群漲幅**，可取代 groups.json 的手動族群。
- **新聞/題材強度**：MoneyDJ 題材頁或 FinLab themes（`modules/themes_scraper.py` 已有爬蟲），尚未接進分數。
- **期貨盤中**：台指期日盤即時與現貨價差（MIS 無；Shioaji `Contracts.Futures.TXF`）。

## 給 Claude 的用法

```bash
python3 monitor.py 3042 --once --json --no-shioaji
```
一行 JSON 含盤前因子、盤中因子、勝率、支撐壓力、計畫，直接拿來做判斷；盤後用 `review.py` 對照。
